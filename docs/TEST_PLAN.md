# План испытаний

Фактические результаты локальной проверки приведены в [отчёте](TEST_RESULTS.md). Ожидаемое поведение ниже само по себе не означает, что каждый сценарий уже прошёл проверку.

## Сквозные сценарии

| Сценарий | Ожидаемый результат |
| --- | --- |
| Покупатель ищет материал, применяет фильтр и открывает карточку | Каталог показывает подходящие позиции, цену в рублях и предложения поставщиков. |
| Администратор добавляет товар, поставщик меняет остаток предложения | Новый товар находится в справочнике; изменённый остаток возвращается при повторном запросе списка предложений. |
| Покупатель сортирует каталог по цене | Товары идут по минимальной цене действующего предложения в выбранном направлении; товары без цены стоят после остальных, выбор и фокус сохраняются при обновлении каталога. |
| Покупатель добавляет товар, меняет количество и оформляет заказ | Сервер пересчитывает сумму, проверяет наличие и фиксирует заказ. |
| Потребность объекта включает два товара разных продавцов | Система показывает общий расчёт и отдельные поставки по продавцам. |
| Калькуляторы плитки, краски и смеси получают граничные и обычные значения | Формула видна пользователю, упаковки округляются вверх, недопустимый ввод отклоняется. |
| Импорт CSV и XLSX содержит правильные и ошибочные строки | Корректные позиции добавляются, ошибочные строки перечисляются без потери исходного файла. |
| Два покупателя одновременно покупают последний остаток | Успешным становится не более одного оформления; отрицательный остаток невозможен. |
| Покупатель повторяет запрос оформления с тем же ключом | Возвращается прежний заказ, резерв не уменьшается второй раз. |
| Покупатель получает список, детали, результат оплаты или отмены заказа | Суммы приходят числами в целых копейках и совпадают с расчётом. Значения из PostgreSQL вне безопасного целочисленного диапазона отклоняются, а не округляются. |
| Поставщик пытается изменить чужое предложение, покупатель — открыть чужой заказ | API возвращает отказ без раскрытия данных. |
| Диспетчер назначает рейс, водитель проходит статусы | Сохраняется допустимая последовательность событий; обратный или чужой переход отклоняется. |
| API читает календарную дату заказа или рейса в часовом поясе Астрахани | Дата приходит строкой `YYYY-MM-DD` и совпадает с введённой; отсутствующая дата остаётся `null`. |
| Покупатель оплачивает учебный заказ, диспетчер назначает водителя, водитель завершает поставку | Все действия доступны через интерфейс соответствующей роли; покупатель видит завершённый заказ с исходной суммой, доставленный остаток не возвращается на склад. |
| Ключи карт и адресного сервиса пусты | Доступны локальные подсказки и статичная схема между фиксированными демонстрационными точками. Адрес заказа не определяет эту схему; движение автомобиля не показывается. |
| Настроенный адресный или маршрутный сервис отвечает ошибкой | API возвращает 502 с соответствующим кодом ошибки; адрес можно ввести вручную. Ошибка запроса маршрута не выдаётся за успешный дорожный маршрут; без загруженной карты отображается демонстрационная схема. |
| Приложение открыто на узком, среднем и широком экране | Навигация, фильтры, формы, таблицы и карта доступны без горизонтальной прокрутки страницы. |
| Покупатель использует клавиатуру | Фокус заметен, переход к содержимому работает; окна и мобильные фильтры удерживают фокус, закрываются Escape и возвращают фокус к кнопке открытия. Выбор файла доступен с клавиатуры, недоступное оформление заказа не активируется. |
| Ответы подсказок или расчётов приходят в обратном порядке | Интерфейс сохраняет результат для текущего адреса и даты; старый ответ не возвращает прежний итог и не разрешает подтверждение. |

Автоматизированные браузерные сценарии находятся в `web/e2e`. Порядок запуска на отдельной базе описан в [инструкции](BROWSER_TESTS.md). Проверки через реальный API и проверки с подменой ответов учитываются отдельно: подмена не подтверждает серверную обработку или работоспособность внешних сервисов.

## Запись результатов

Отдельно проверяется каталог: границы цены включаются в диапазон, цена и сортировка используют один минимум активных предложений; с фильтром наличия предложения с нулевым остатком исключаются. Число результатов совпадает с выборкой до разбивки на страницы. Категория, поиск и диапазон работают вместе. Неверные, повторяющиеся и обратные границы API отклоняет. В мобильной панели проверяются Escape, закрытие по фону, возврат фокуса и снятие блокировки прокрутки при смене размера экрана.

Для каждого запуска отмечаются дата, версия Git, конфигурация, команда, результат и ссылка на снимок экрана или вывод теста. Отдельно записываются ограничения: работа внешних сервисов проверяется только при наличии новых ключей и сети; демоплатёж не является банковской операцией; карта показывает статичную демонстрационную схему, симуляция движения и GPS отсутствуют. Проверка маршрута к адресу конкретной поставки и анимации возможна после реализации этих функций; в выполненные испытания они не включаются.

## Сравнение пользовательского процесса

Сравнительное испытание пока не проведено. В запланированном испытании для одинакового подготовленного набора материалов измеряются ручное составление заказа и выполнение через «ОбъектМаркет». Записываются время, число действий, ошибки, сумма товаров и доставки. Испытание проводится по сценариям из `RESEARCH.md`; результаты и условия записываются без округления в пользу системы.
