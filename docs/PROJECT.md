# Описание проекта

## Назначение

«ОбъектМаркет» помогает подобрать строительные материалы для покупки или конкретного объекта. Для объекта система объединяет перечень потребности, предложения продавцов, доступные остатки, стоимость доставки и сроки поставки. Основной проверяемый результат ВКР — сквозное формирование закупки с учётом этих условий.

Тема ВКР: «Разработка информационной системы выбора и поставки строительных материалов с учётом потребностей строительного объекта». Направление: АГАСУ, 09.03.02 «Информационные системы и технологии», профиль «Информационные системы и технологии в строительстве и архитектуре». Предварительные данные автора: Бальдюсов Кирилл Андреевич, группа ЗИТ-51-22. Формальные реквизиты и требования к оформлению уточняются по методическим материалам вуза.

## Функции релиза

1. Каталог, поиск, фильтры, предложения нескольких поставщиков, корзина и заказ.
2. Объекты строительства, импорт перечня материалов из CSV/XLSX, калькуляторы плитки, краски и сухих смесей.
3. Сравнение предложений по доступности, сроку и полной стоимости с доставкой; группировка заказа по поставщикам.
4. Кабинеты покупателя и поставщика, план поставок диспетчера, рейсы водителя, отчёты администратора.
5. 2ГИС для карты и маршрута и DaData для адреса при наличии действующих ключей. Без ключей — явно обозначенные локальные данные и симуляция движения.

Денежные средства не списываются. Движение машины в учебной версии моделируется; реальный GPS не заявляется. Учебные поставщики, объекты и заказы вымышлены.

## Архитектура и данные

Интерфейс: Next.js, React, TypeScript. Сервер: NestJS API на TypeScript. Хранилище: PostgreSQL с миграциями и повторяемой загрузкой демоданных. Запуск на ноутбуке: Docker Compose. Отдельная инструкция предусмотрена для Ubuntu VPS. Единый язык на клиенте и сервере упрощает изучение, сопровождение и защиту проекта.

Основные сущности: пользователь и роль, поставщик, товар, предложение, складской остаток, объект, потребность, заказ, позиция заказа, поставка, маршрут и событие статуса. Изменение остатков при оформлении заказа выполняется транзакционно. Доступ к данным ограничен ролью и владельцем.

Публичный API описан в OpenAPI под `/api/v1`. Ключи внешних сервисов задаются переменными окружения. Деморежим запускается без ключей и сети.

## Критерии готовности

- Чистый локальный запуск по README и повторяемая загрузка демоданных.
- Сквозной сценарий от выбора товара до завершения учебной поставки.
- Проверенные роли, остатки, расчёты, ошибки внешних сервисов и режим без ключей.
- Адаптивный интерфейс в светлой и тёмной темах, проверенный на телефоне, планшете и большом экране.
- Документация, текст ВКР, презентация, выступление и ответы на вопросы на русском языке.
