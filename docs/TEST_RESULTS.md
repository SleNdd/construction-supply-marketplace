30 сентября также повторены `npm test` для API (16 из 16), сборка API, lint, typecheck и сборка интерфейса. Четыре новых модульных теста проверяют JSON-числа для итогов заказа, границы точного диапазона JavaScript и отказ на повреждённой сумме, а также смену календарного дня Астрахани в 20:00 UTC. Интеграционный тест и `npm run smoke` прошли на отдельной PostgreSQL 17 при `TZ=Europe/Astrakhan`: строки календарных дат заказа и рейса совпали с заданными `YYYY-MM-DD`, отсутствующие даты остались `null`. Это проверка API с указанным часовым поясом; в других поясах отдельного прогона не было.

Параллельный тест проверяет конкретное выполнение. Все варианты чередования транзакций тест не перебирает; порядок блокировки общего заказа перед поставкой задан в обработчике событий.

В браузерном тесте задержек старые запросы освобождаются после нового ответа; перед проверкой интерфейса ожидается их завершение либо отмена. Проверки с подменой ответов испытывают клиентскую обработку и не подтверждают работу серверов DaData/2ГИС. Другие браузеры и полный аудит доступности этим набором не покрыты. Инструкция воспроизведения — [браузерные испытания](BROWSER_TESTS.md).

Тестовые заказы добавляются в локальную демонстрационную базу. Они не являются данными действующей компании. Платёж меняет только учебный статус, а маршрут на карте без ключа является схемой. Работа с действующими ключами и отказами реальных 2ГИС/DaData в этом запуске не испытывалась. Испытание с участниками и замер времени ручной закупки не проводились; выводов об экономии времени или денег по этим проверкам нет.


## Проверка обновления от 1 октября

Среда: Windows, Node.js 25.8.1, временная PostgreSQL 17 без постоянного тома, API 4100 с `TZ=Europe/Astrakhan`, Next.js 3100, Chromium. Основная база Docker Compose не использовалась для автоматических сценариев. Интеграционный набор, smoke и браузерный набор запускались последовательно на тестовой базе; действующие ключи не задавались.

- `api/npm test`: 26 из 26 пройдены. Добавлены пределы всех входов и результатов трёх калькуляторов, малые упаковки, underflow, нулевой запас, границы целой упаковки, переходы месяца/года и согласованность ближайшей даты в карточке и quote. Малый положительный расход не отображается как ноль.
- `api/npm run test:integration` и `npm run smoke`: пройдены. Дополнительно проверен чужой PATCH объекта: 404, весь непустой объект владельца сохранён без изменений.
- API build, web lint, typecheck и production build: пройдены. OpenAPI разобран как YAML; числовые пределы и ответ 400 описаны.
- `web/npm run test:e2e`: 38 из 38 проверок за 54,1 с. Это 37 браузерных сценариев и одна проверка денежного форматирования в том же наборе Playwright. Девять сценариев выполняют предметные операции через настоящий API; остальные проверяют представление, браузерное хранилище или обработку подготовленных ответов.

Редактор объекта проверен с материалом в перечне: отмена, ошибка PATCH, повтор, сохранение состава, адреса и имени после перезагрузки. В плане проверены запоздавшие ответы при смене количества, даты, адреса и предложения; изменившийся срок, общий дефицит двух потребностей одного предложения и оба лимита корзины. При превышении лимита план не переносится частично.

Сравнение проверено с подготовленными ответами: цена с доставкой меняет исходный выбор поставщика, количество и срок меняют доступность, ошибка одной карточки допускает отдельный повтор. Отказ quote, адрес вне зоны и изменение срока/остатка блокируют корзину; обновление получает новый результат. Мобильные карточки проверены на 390 px в обеих темах и с reduced motion. Проверены повреждённые JSON/массивы/отдельные записи корзины, дубли и предел сравнения в четыре товара. Строка bigint отчёта сохраняет копейки выше безопасного диапазона Number. Локальная фотография товара показывается вместо фотографии категории; при её отказе используется запасная фотография категории.

Первый расширенный прогон дал 31 из 33: не проходили поиск поля по точной подписи и слишком широкий locator уведомления. Явная связь label с полем и область поиска уведомления исправлены; утверждения о поведении сохранены. Приведённый выше результат относится к повторному полному прогону.

Docker Compose пересобран; PostgreSQL и API healthy, сайт доступен на 3000. Это проверка обновления существующего стенда. Новый чистый запуск без тома, проверка живых внешних ключей, восстановление резервной копии и испытание с участниками остаются отдельными работами. HTTPS-фотография и сохранение изображения через администратора в этом браузерном наборе не проверены. Макеты Word/PPTX/PDF этим прогоном не подтверждаются.

После сокращения вводного текста сравнения и переноса пояснения в раскрываемый блок повторены production build и восемь затронутых сценариев сравнения: 8 из 8 за 9,9 с. На действующем Compose отдельно просмотрено сравнение двух материалов при ширине 390, 1024 и 1440 px; сохранён [снимок широкого экрана](screenshots/comparison.jpg). Автоматическая проверка двух тем выполнена в сценарии сравнения; полный визуальный аудит всех экранов не заявляется.
