# Браузерные испытания

Playwright запускает Chromium и проверяет приложение через интерфейс. Для испытаний используются отдельная база с учебными данными и свои процессы API и Next.js. Разделение с рабочим демо обеспечивается отдельными портами, процессами и базой. Рабочее демо на порту 3000 для этого не подходит: сценарии создают объекты и заказы, отменяют неоплаченный заказ и завершают учебную поставку.

## Локальный запуск на Windows

Нужны Node.js 22, npm и работающий Docker. Команды выполняются из каталога проекта. В первом терминале подготовьте временную PostgreSQL:

```powershell
docker run --name obektmarket-browser-test --rm -d -p 127.0.0.1:5435:5432 -e POSTGRES_DB=obektmarket_test -e POSTGRES_USER=obektmarket -e POSTGRES_PASSWORD=browser-test-password postgres:17-alpine
for ($attempt=0; $attempt -lt 30; $attempt++) {
  docker exec obektmarket-browser-test pg_isready -U obektmarket -d obektmarket_test > $null
  if ($LASTEXITCODE -eq 0) { break }
  Start-Sleep -Milliseconds 500
}
if ($LASTEXITCODE -ne 0) { throw 'PostgreSQL не готова к подключению' }
cd api
$env:DATABASE_URL='postgres://obektmarket:browser-test-password@localhost:5435/obektmarket_test'
$env:DEMO_SEED='true'
$env:API_PORT='4100'
$env:CORS_ORIGIN='http://localhost:3100'
$env:COOKIE_SECURE='false'
$env:DADATA_API_KEY=''
$env:GIS_ROUTING_KEY=''
npm ci
npm run migrate
npm run seed
npm run build
npm run start:prod
```

Дождитесь сообщения о запуске API. Если миграция, загрузка данных или сборка завершились с ошибкой, исправьте её до продолжения.

Во втором терминале из каталога проекта:

```powershell
cd web
$env:API_INTERNAL_URL='http://localhost:4100'
$env:PUBLIC_ORIGIN='http://localhost:3100'
npm ci
npx playwright install chromium
npm run build
npm run test:e2e
```

Тестовый сервер Next.js на порту 3100 запускается и останавливается конфигурацией Playwright. Браузерные сессии отдельных тестов не делят cookies и локальную корзину. Реальные сценарии используют подготовленный API, а тесты гонок ответов подменяют только необходимые HTTP-ответы. Такая подмена проверяет поведение интерфейса и не подтверждает работу внешнего сервиса.

После испытания остановите API сочетанием Ctrl+C и выполните:

```powershell
docker stop obektmarket-browser-test
```

У этого контейнера нет постоянного тома, поэтому его тестовая база будет удалена вместе с контейнером. Данные основного Compose-стенда сохраняются.

## Отчёт и CI

Набор содержит 38 проверок: 37 браузерных сценариев и одну проверку точного денежного форматирования. Девять сценариев выполняют предметные операции через настоящий API: поиск, фильтры каталога, мобильная панель, покупка с объектом и отменой, полный путь поставки, мобильный выбор предложения, изменение непустого объекта, остатка поставщиком и создание товара администратором.

В поставке покупатель подтверждает демооплату, диспетчер назначает водителя, водитель отмечает загрузку и доставку, покупатель видит завершённый заказ. Проверяются суммы, водитель, статусы, остаток и календарная дата рейса в браузере с другим часовым поясом. Редактор объекта проверяет ошибку и повтор PATCH, отмену, возврат фокуса и сохранение материалов после перезагрузки. Тест поставщика восстанавливает остаток запросом API даже при неуспехе; созданный администратором товар остаётся только во временной базе.

Подготовленные ответы используются в проверках задержек checkout, плана объекта и сравнения, отказа расчёта, зоны, срока и остатка. Они испытывают клиентскую обработку, а не реальный внешний сервис. Старые ответы освобождаются после нового, перед assertions ожидается завершение либо отмена конкретного запроса. Браузерное хранилище проверяется с повреждёнными значениями, отдельными строками, дублями и лимитами. Локальная фотография и её отказ проверяются в карточке; HTTPS-провайдер изображения не испытывается.

Главная проверяется на 390 и 1440 px; сравнение — на 390 px в светлой и тёмной темах с reduced motion. Проверяется отсутствие горизонтального переполнения. Результаты и условия конкретного прогона приведены в [отчёте](TEST_RESULTS.md).

Для просмотра локального отчёта: `npx playwright show-report` из `web`. При неуспешном сценарии сохраняются трасса и снимок экрана. Каталоги `playwright-report` и `test-results` исключены из Git и Docker-контекста.

GitHub Actions использует свою PostgreSQL 17, применяет миграции, загружает демоданные, собирает API и интерфейс, затем запускает те же тесты. Отчёт доступен в артефакте `browser-test-report` в течение семи дней. Проверки не обращаются к действующим DaData/2ГИС и не выполняют банковскую оплату.
