# Запуск и развёртывание

## Локальная демонстрация

Нужны Docker Engine или Docker Desktop с Compose и свободный порт 3000. Скопируйте `.env.example` в `.env`, замените `POSTGRES_PASSWORD` и `SESSION_SECRET` на собственные значения. Для учебного запуска ключи 2ГИС и DaData можно оставить пустыми.

```bash
docker compose up --build -d
docker compose ps
```

Откройте `http://localhost:3000`. При первом старте API применяет миграции и добавляет демоданные. Повторный старт не должен удалять созданные заказы. Для диагностики используйте `docker compose logs --tail=100 api web db`. Команда `docker compose down` останавливает контейнеры и сохраняет данные PostgreSQL в именованном томе.

Ключ тайлов 2ГИС передаётся в `GIS_MAP_KEY`, маршрутизации — в `GIS_ROUTING_KEY`, адресных подсказок — в `DADATA_API_KEY` и, если требуется выбранному методу, `DADATA_SECRET_KEY`. Ключ карты виден браузеру и должен быть ограничен по домену в кабинете провайдера. Серверные ключи в браузер не передаются. После изменения ключа карты пересоберите веб-образ. Без ключей интерфейс явно показывает деморежим.

## Ubuntu VPS

Рекомендуемая схема: Ubuntu с Docker Engine и Compose, приложение в отдельном системном каталоге, HTTPS обратный прокси перед портом 3000, доступ к PostgreSQL только внутри Compose. Скопируйте чистый релиз, создайте `.env` с уникальными секретами, задайте домен и сертификат в обратном прокси, затем выполните `docker compose up --build -d`. Ограничьте входящие порты 80/443 и SSH; порт PostgreSQL не публикуется. Настройте регулярный `pg_dump` в защищённое хранилище и проверьте восстановление на отдельной базе.

Учебные пароли и демоданные не предназначены для публичного сервиса. Перед реальным размещением замените их, создайте пользователей и перепроверьте настройки сессий, доменные ограничения ключей, права доступа и политику хранения персональных данных. В рамках ВКР VPS не разворачивается; инструкция описывает воспроизводимый путь.
